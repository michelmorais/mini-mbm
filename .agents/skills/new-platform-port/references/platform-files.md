# Per-Platform File Reference

## Linux (`platform-linux/`)

| File | Purpose | Required? |
|---|---|---|
| `main.cpp` | C++ mode entry point — `int main()` calls `GAME::initGraphics` + `loop` | C++ mode |
| `main-lua.cpp` | Lua mode launcher — calls `mbm::` API from `mini-mbm-lib.h` | Lua mode |
| `my-scene.h` | `MY_SCENE : mbm::SCENE` + `GAME : mbm::CORE_MANAGER` declarations | Both modes |
| `my-scene.cpp` | Implements all virtual scene methods | C++ mode |
| `.clang-tidy.sh` | Optional clang-tidy helper script | No |
| `README.md` | Build prerequisites + commands | No |

Lua mode also requires `src/mini-mbm-lib/mini-mbm-lib-Linux.cpp`.

## macOS (`platform-macos/`)

| File | Purpose | Required? |
|---|---|---|
| `main.cpp` | C++ mode entry point — identical pattern to Linux | C++ mode |
| `main-lua.cpp` | Lua mode launcher — identical pattern to Linux | Lua mode |
| `my-scene.h` | **Identical content** to Linux `my-scene.h` | Both modes |
| `my-scene.cpp` | **Identical content** to Linux `my-scene.cpp` | C++ mode |
| `README.md` | Build prerequisites + commands | No |

Lua mode also requires `src/mini-mbm-lib/mini-mbm-lib-MacOs.mm` (ObjC++, `-fobjc-arc`).
Render backend is Metal; no OpenGL ES available on macOS.

## Android (`platform-android/`)

| File | Purpose | Required? |
|---|---|---|
| `main-native-activity.cpp` | **Primary entry** — NativeActivity via `android_native_app_glue`; JNI functions `MiniMbmEngine_*` | Both modes |
| `main.cpp` | Legacy JNI entry using `MbmActivity.java` and `scene-1.h` | Alternate/legacy |
| `main-lua.cpp` | Lua mode JNI variant | Lua mode alt |
| `my-scene.h` | `MY_SCENE` + `MY_GAME : mbm::CORE_MANAGER` (note: `MY_GAME`, not `GAME`) | C++ mode |
| `my-scene.cpp` | MY_SCENE implementation | C++ mode |
| `scene-1.h`, `scene-1.cpp` | Alternative scene used by legacy `main.cpp` | Legacy only |
| `AndroidManifest.xml` | Android app manifest | Deploy |
| `MbmActivity.java` | Java NativeActivity entry class | Deploy |
| `com/`, `gradle/`, `templates/` | Android Studio project templates (generated by CMake) | Deploy |
| `README.md` | Prerequisites + NDK setup + build commands | No |

Key differences from desktop platforms:
- Output is `add_library(mini-mbm SHARED …)` — **not** `add_executable`
- No `int main()`; entry is via `android_main()` in `android_native_app_glue`
- JNI functions bridge Java ↔ C++: `MiniMbmEngine_init`, `MiniMbmEngine_loop`, `MiniMbmEngine_onTouchDown`, etc.
- All plugins must be statically linked (see `src/CMakeLists.txt` Android workaround blocks)
- `export NDK_ROOT=~/android-ndk-r29` required before cmake
- cmake toolchain file: `${NDK_ROOT}/build/cmake/android.toolchain.cmake`
- `--whole-archive` linker flag required for `android_native_app_glue` to export `ANativeActivity_onCreate`

## iOS (`platform-ios/`)

| File | Purpose | Required? |
|---|---|---|
| `main-lua.mm` | UIApplicationMain entry — both C++ and Lua modes | Both modes |
| `AppDelegate.h` / `AppDelegate.mm` | `UIApplicationDelegate` — creates `UIWindow` | Both modes |
| `MBMMetalView.h` / `MBMMetalView.mm` | CAMetalLayer-backed UIView | Both modes |
| `MetalViewController.h` / `MetalViewController.mm` | UIViewController hosting MBMMetalView; calls engine init in `viewDidLoad` | Both modes |
| `my-scene.h` | `MY_SCENE : mbm::SCENE` + `GAME : mbm::CORE_MANAGER` declarations | C++ mode |
| `my-scene.mm` | MY_SCENE implementation (ObjC++ format) | C++ mode |
| `Info.plist.in` | CMake template configured to `Info.plist` with `GAME_BUNDLE_ID` / `GAME_NAME` | Both modes |
| `Info.plist` | Generated by `configure_file` — do not edit manually | Generated |
| `README.md` | Build generator options, Xcode vs make | No |

Key differences:
- **All** platform `.mm` files compiled with `-fobjc-arc`
- `MACOSX_BUNDLE TRUE` + `MACOSX_BUNDLE_INFO_PLIST` set on target
- Two CMake generators: plain `make` (unsigned binary, CI checks) and `-G Xcode` (signed deploy)
- Plugin static linking mandatory (App Store sandbox); box2d + box2d-liquid-fun conflict → box2d wins with `USE_ALL=1`
- `GAME_BUNDLE_ID`, `GAME_NAME`, `GAME_ASSETS_DIR` CMake variables control the generated `.xcodeproj`
- Assets bundled via `MACOSX_PACKAGE_LOCATION` source property (Xcode generator) or `POST_BUILD copy_directory` (make generator)

## `src/mini-mbm-lib/` — Platform Launcher Files

| File | Platform | Notes |
|---|---|---|
| `mini-mbm-lib.cpp` | All (Lua mode) | Common launcher logic |
| `mini-mbm-lib-Linux.cpp` | Linux | POSIX window/event loop |
| `mini-mbm-lib-MacOs.mm` | macOS | Cocoa/NSWindow; ObjC++; `-fobjc-arc` |
| `mini-mbm-lib-Windows.cpp` | Windows | Win32 window/event loop |
| `mini-mbm-lib-iOS.mm` | iOS | UIKit; ObjC++; `-fobjc-arc` |
| `mini-mbm-lib.h` | All | Public API (`mbm::loop`, `mbm::set_scene`, etc.) |
